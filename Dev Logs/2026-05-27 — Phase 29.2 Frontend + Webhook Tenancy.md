# Phase 29.2 — Strict Multi-Tenancy: Frontend & Webhook Integration

## Goal

Close two gaps left by Phase 29.1:

1. **Frontend**: make the SPA tenant-aware. Pick a workspace on login, switch in-shell, inject `X-Tenant-ID` on every request, expose a `/settings/workspaces` admin page.
2. **Webhook**: map inbound Meta page ids → internal tenant UUIDs so Messenger traffic enters the LangGraph cortex already locked to a workspace (no more `_tenant_filter` raises mid-graph).

## Architect interactions

The directive prescribed TypeScript + Zustand + Axios + React Query for the frontend and a fresh `rag/routers/webhooks.py` for the webhook router. Both were pushed back on (per CLAUDE.md §6.2 "Hands and Eyes Rule") and approved by the architect:

- **Frontend stack**: kept JS + `fetch` + React Context to match the existing 18-page SPA. Built `TenantProvider` mirroring the existing `AuthProvider` pattern; `apiFetch` got tenant + 403 interceptor hooks; switching workspaces remounts the authenticated subtree via a `key={activeTenantId}` on `RequireTenant` — functional equivalent of a React-Query cache wipe.
- **Webhook router**: the Messenger webhook lives at `rag/messenger/routers/webhook.py` (Phase 6 + Phase 12), not `rag/routers/webhooks.py`. Extended the existing router and added a new `rag/messenger/tenant_resolver.py` module instead of duplicating the surface.

## What shipped

### Backend

- **`MessengerPageTenant`** ORM model + Alembic migration `0003_phase29_messenger_page_tenants` (single table with `facebook_page_id` PK, `tenant_id` FK to `app.tenants`, indexed for fast lookup).
- **`rag/messenger/tenant_resolver.py`** — `resolve_tenant_for_page(db, page_id) → Tenant | None`. Defensive on empty input; never raises.
- **`run_graph(tenant_id=...)`** — new kwarg propagates the tenant slug into `NexusState["tenant_id"]` so `_tenant_filter` finds it.
- **Messenger webhook wiring**:
  - Direct Meta path (`POST /webhook/messenger/inbound`) resolves the tenant per coalesced event group. Unmapped page ids drop cleanly with `messenger.event.no_tenant_mapping` (200 to Meta — never 5xx, which would trigger retry storms).
  - Broker path (`POST /webhook/messenger/orchestrator`) accepts a pre-resolved `tenant_slug` on the payload OR resolves from `page_id` on the way in. Unresolved payloads get `status="rejected"` (not 5xx) so the orchestrator surfaces the cause cleanly.
- **`InboundMessage`** gained `tenant_id: UUID | None` and `tenant_slug: str | None` (populated server-side; the broker path's `X-Webhook-Api-Key` gate prevents external smuggling).

### Frontend

- **`TenantProvider`** owns the active workspace. On auth flip-truthy: `GET /api/tenants`, auto-select the only tenant (single-workspace happy path), restore persisted choice (`localStorage.nexus_tenant_id`), or surface `WorkspacePickerModal`.
- **`apiFetch` interceptor** injects `X-Tenant-ID` on every request **except** the whitelist (`/auth/jwt/login`, `/auth/jwt/logout`, `/users/me`, `/tenants` and `/tenants/<id>`) — the pre-selection bootstrap surface.
- **403 boundary**: any tenant-scoped endpoint returning 403 calls `TenantProvider.reset()` → clears local storage + active id → bounces user to picker.
- **`WorkspaceSwitcher`** dropdown in `PageHeader` (Building2 icon + workspace name + role badge).
- **`/settings/workspaces`** page (list + create form, sidebar nav entry under Settings). Successful create appends to the dropdown and switches active tenant without a hard reload.
- **Cache invalidation**: `RequireTenant` keys its children on `activeTenantId` so a workspace switch forces a full subtree remount — every page's `useEffect` reruns, every hook-owned cache flushes. No per-page edits required.

### Tests

- **`rag/messenger/tests/test_phase29_tenancy.py`** (7 tests, all green):
  - Resolver unit: hit, miss, empty page_id short-circuit.
  - Direct webhook: unmapped page drops event with 200 (no scheduled task); mapped page passes `tenant_id` + `tenant_slug` into the runner.
  - `run_graph(tenant_id="hunter")` populates `state["tenant_id"]`; omitted leaves it unset.
- **Messenger conftest** got an autouse fixture (`stub_tenant_resolution`) so the 100+ existing webhook tests keep running without Postgres: it overrides `get_async_session` and monkeypatches the resolver to a default Hunter tenant. New tenancy tests inject their own routing table.
