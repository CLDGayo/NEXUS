# Phase 32.1 — Bug Triage & UX Refactoring

## Context

Phase 32 (Product Catalog + Meta Generic Template carousel) shipped earlier today. Manual testing surfaced five regressions across the SPA, the product image pipeline, and the chat stream. The Architect (Gemini) triaged the bugs and requested a single comprehensive hotfix. Plan was diagnosed, approved, executed, and deployed in one session.

## Bugs fixed

1. **Duplicated top nav bar on `/products` and `/products/:id`** — both pages self-imported and rendered `<PageHeader />` while `AppShell.jsx` already mounts one above the `<Outlet />`. Architect's hypothesis blamed `RequireOwner`; the actual guard ([RequireOwner.jsx:52](nexus-ui/src/components/auth/RequireOwner.jsx#L52)) was already a clean `return <Outlet />`. Fix: dropped the page-level `<PageHeader />`, relocated the "New" / "Back" affordances into inline toolbars, and added a regex `MATCHERS` fallback to `AppShell.TITLES` for the `/products/:id` route.
2. **Broken-file icon in product list view** — `image_url` was persisted at upload time as `public_url_for(key)`, which returns `None` whenever `MINIO_PUBLIC_BASE_URL` is unset (prod state). DB rows stored `NULL` forever; `<img src={null}>` rendered the broken-icon glyph.
3. **Grey "loading…" stuck thumbnails in the carousel editor** — same root cause as Bug 2; the carousel's `{image.image_url ? <img/> : <div>loading…</div>}` ternary stayed on the placeholder branch forever.

   Fix for 2 + 3: changed `_serialize_image` in `rag/routers/products.py` to an `async` function that mints a 1-hour presigned MinIO GET URL via `presigned_get_url(...)` whenever `public_url_for` returns `None`. Propagated `await` through every caller; batched parallel presigns with `asyncio.gather` bounded by an `asyncio.Semaphore(20)`. Existing rows with `image_url = NULL` now render correctly without a data migration. Mirrors the avatar-router pattern but resolves URLs at serialization time rather than via a dedicated endpoint (products list is owner-only / low fan-out, so an extra round-trip per thumbnail wasn't worth the complexity).

4. **Image uploader hidden on new-product form** — `ProductForm` gated `<ImageCarouselEditor>` behind `isEditing` because `uploadProductImage(productId, file)` requires a `product_id`. Forced the user to save the product before they could attach images.

   Fix: dropped the `isEditing` gate; the carousel now runs in a "staged" mode when `productId == null`. Files buffer into local state with `URL.createObjectURL(file)` previews. On submit, `ProductForm` does `createProduct` → loop `uploadProductImage` over the staged blobs → call `onSaved(merged)`. `useEffect` cleanup in the carousel revokes any lingering blob URLs on unmount.

5. **Chat stream 400 "missing X-Tenant-ID"** — `sse.js:chatStream()` used a bare `fetch()` that only carried `authHeaders()`. The standard `apiFetch` tenant interceptor was bypassed. Architect's hypothesis blamed the FormData/multipart path; correction: `api.upload()` (FormData) DOES inject the tenant. The actual bug was in the SSE open call, and it has been silently tenant-blind since the file was written — the symptom only became loud after attachments raised user attention.

   Fix: exported `getActiveTenantId()` from `nexus-ui/src/lib/api.js`, read it in `sse.js`, and injected `X-Tenant-ID` into the stream headers. Kept SSE on a hand-rolled `fetch` rather than routing through `apiFetch` (which would JSON-parse the body and break the stream).

## Notes for the Architect

- §6.1 push-back: refined two of the hypotheses (`RequireOwner` was clean; FormData uploads carried the tenant header). Real culprits were inside the product pages and the SSE module respectively.
- Presigned URLs carry a 1-hour TTL. A long-open dashboard could see expired URLs; the list re-fetches on `cacheVersion` bumps, so a navigation away-and-back refreshes. If this becomes a real issue, Phase 32.2 should either set up `MINIO_PUBLIC_BASE_URL` with an anonymous-read policy or stand up a CDN.
- The "Save once to upload images" copy has been replaced with "Drop images now — they upload after you click 'Create product.'" which appears only when no images are staged.
- The pre-existing `mypy --strict` errors on `routers/products.py` are namespace/import-resolution issues (rag.* not resolvable from `cwd=rag/`); they're inherited from Phase 32 and not new in this hotfix.
