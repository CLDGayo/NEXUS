# Phase 32.2 — Post-Deploy Triage

## Context

Phase 32.1 deployed cleanly, but live verification on https://chat.nexus.gayo-sphere.cloud immediately surfaced three follow-up issues:

1. Product images on `/products` and `/products/:id` still rendered as broken-icons.
2. Chat send returned `404 {"detail":"session not found"}` (32.1 promoted the symptom from `400 missing X-Tenant-ID` to `404`).
3. User reported newly-created products should also appear in the Documents view (scope addition).

Live diagnostics confirmed:

- The 32.1 presigned-URL fallback fires correctly, but the URL it emits embeds `http://nexus-minio:9000/...` — the internal Docker DNS name. The browser cannot resolve that hostname. Probed live: `nexus-minio` exposes only 9000/tcp on the internal docker network, no host port mapping, no public DNS for `minio.nexus.gayo-sphere.cloud` (NXDOMAIN), `MINIO_PUBLIC_BASE_URL` empty in `.env.prod`.
- `app.chat_sessions` had 0 rows for any tenant. The SPA mints a fresh client-side UUID via `crypto.randomUUID()` on every load and sends it to `/api/chat/stream`; the backend's `_resolve_session` refused any UUID it didn't mint itself. Lifecycle mismatch since Phase 27.
- The Documents endpoint reads `app.documents` only; products live in `app.products` and were invisible.

## Bugs fixed

1. **Image broken-icons** — Production MinIO is intentionally private. Rather than block on infra work (CloudPanel vhost, DNS, LetsEncrypt cert), this hotfix streams the image bytes through the existing API. New module `rag/services/object_proxy.py` mints short-lived JWT-signed tokens (using `settings.nexus_jwt_secret`, audience `nexus:object-proxy`). New route `GET /api/objects/{token}` decodes the token, fetches via the internal s3 client, and returns a `StreamingResponse`. `_mint_image_url` in [rag/routers/products.py](rag/routers/products.py) now returns `/api/objects/<token>` instead of a presigned URL. The proxy is a no-op fallback the moment `MINIO_PUBLIC_BASE_URL` is set (32.3 or later).

2. **Chat 404 session not found** — `_resolve_session` ([rag/routers/chat.py](rag/routers/chat.py)) lazy-creates a `ChatSession` row when the client-supplied `session_id` has no backing row. Concurrent first-turn race is recovered by catching `IntegrityError`, rolling back, and re-reading the winning insert. Cross-tenant ownership check stays in place after the read.

3. **Products in Documents view** — [rag/routers/documents.py](rag/routers/documents.py) `GET /api/documents` now runs a parallel `app.products` query (tenant-scoped) alongside the notes query, maps each `Product` to the row shape via `_product_to_doc_dict()` (path `/products/{slug}`, folder `/products`, tags `["product"]`, source_kind `"product"`), concatenates + sorts by `modified` desc, and paginates after concatenation. SPA needs no change — same row shape, same column rendering.

## Notes for the Architect

- §6.1 corrections from this round: (a) the previous Phase 32.1 presigned-URL fallback DID execute on prod — the deploy was fine, but the URL it emitted leaked the internal Docker hostname `nexus-minio:9000` which no browser can reach; (b) the 32.1 SSE tenant-header fix DID land — what the user saw afterwards (`404 session not found`) is a latent Phase 27 lifecycle bug that was masked by the upstream `400`.
- Token security: the proxy URL uses the existing `NEXUS_JWT_SECRET`. A stolen URL works on one object for ≤1 hour, same blast radius as a presigned URL. Tenant isolation preserved because `mint_token` is only invoked inside owner-gated serialization paths.
- Bandwidth: each thumbnail flows MinIO → API → browser. For owner traffic at typical sizes (10 products × 1 hero × ~150KB), trivial. Phase 32.3 should consider standing up a CloudPanel-fronted public MinIO vhost (`minio.nexus.gayo-sphere.cloud` → `127.0.0.1:9000` after port mapping) so future avatars + a larger catalogue can bypass the proxy.
- Vector-chunks counter on the Documents page still shows `0` because the ingest pipeline hasn't run; orthogonal to this PR. Tracked under the pre-existing ingestion follow-up.
